JDBC Interview Questions


Q1. What are the differences between Statement and PreparedStatement?
PreparedStatement parses once and reuses the query with different parameters. Statement parses the query every execution.
Q2. Why and when PreparedStatement is used?
When the same query is executed multiple times with different parameters.
Q3. What is a transaction and how you can handle transactions in JDBC?
A transaction is an atomic unit of work. Handle it using setAutoCommit(false), commit(), and rollback().
Q4. What is a commit and rollback in a transaction?
Commit permanently saves changes. Rollback undoes uncommitted changes if an exception occurs before commit.
Q5. What is a stored procedure and how can you call it from JDBC?
A Stored Procedure is a collection of SQL statements stored in the database. Call it using CallableStatement and Connection.prepareCall().
Q6. What are IN, OUT, and INOUT arguments of CallableStatement?
IN sends values, OUT receives values, INOUT does both.
Q7. How you can retrieve multiple ResultSets from CallableStatement?
Use getMoreResults() to process multiple ResultSets.
Q8. How you can retrieve a String return value from CallableStatement?
Use getString().
Q9. What is MetaData and how you can get it?
Metadata is data about the database. Use ResultSetMetaData or DatabaseMetaData.
Q10. How many types of drivers in JDBC?
Four: JDBC-ODBC Bridge, Native, Middleware, Pure Java.
Q11. Which type of driver have you used in JDBC?
Pure Java Driver.
Q12. Where do you find concrete classes of Statement and PreparedStatement?
In the JDBC driver JAR implementing java.sql interfaces.
Q13. What is a Data connection pool?
A pool of reusable database connections created at application startup.
Q14. Advantages of a database connection pool?
Performance, connection reuse, max connection control, supports concurrent users.
Q15. Configure DCP?
As a DataSource in web applications.
Q16. JDBC Bridge Design Pattern?
Interfaces + different driver implementations; DriverManager uses Factory pattern.
Q17. What is NBPK?
An auto-increment primary key with no business meaning.
Q18. How did you create NBPK?
Auto-increment integer column as primary key.
Q19. Advantage of NBPK?
Performance, integrity, normalization, simple design.
Q20. Disadvantage of Business Primary Key?
Business values can change causing foreign-key issues.
Q21. What is normalization?
Removing redundancy and organizing data.
Q22. Normalization forms?
1NF, 2NF, 3NF, BCNF.
Q23. Atomic value?
A value that cannot be divided further.
Q24. What is De-normalization?
Duplicating data to improve query performance.
Q25. When do you use de-normalization?
For time-critical reports.
Q26. Why does de-normalization save time?
Reduces JOIN operations.
Q27. How do you call Stored Procedure and Function from JDBC?
Using CallableStatement.
Q28. registerOutParameter()?
Registers an OUT parameter and its JDBC type.
Q29. Disadvantage of Stored Procedure?
Database dependent.
Q30. When do you use Stored Procedure?
For high-performance reporting.
Q31. Can you configure DCP in Desktop application?
Yes, using DCP libraries.
Q32. How many DCP for one Database?
One DCP per database.
Q33. Which library for DCP?
C3P0.
Q34. Which jars for C3P0?
c3p0 and mchange-commons-java.
Q35. Which DCP in Spring Boot?
HikariCP.
Q36. Can you make application without DCP?
Not recommended for production.
